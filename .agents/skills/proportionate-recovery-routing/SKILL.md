# Proportionate recovery routing

## Contract

- **What:** A bounded method for turning an observable collaboration strain into
  one fitting recovery move and a verified continuation route.
- **When:** A materially useful task cannot continue reliably because an
  evidence path, source relation, permission boundary, context carrier, or
  coordination state has become unclear or unavailable.
- **Boundaries:** Recovery preserves the current contract, exact identities,
  privacy and publication limits, decision authority, and accepted source
  state. A route describes the next useful move; it does not grant permission,
  broaden scope, or turn an unresolved result into acceptance.
- **Result:** The receiver can see the observed strain, the state that remains
  protected, the owning surface, one primary move, its stopping event, the
  compact evidence record returned, the dimensions restored, the remaining
  strain, and the exact re-entry condition.

## Fit and attention

- **Useful when:** A broad failure can be narrowed into an observable layer,
  coordinate, state transition, or receiving decision.
- **Poor fit when:** The task is proceeding normally or direct correction is
  already obvious and verified. Ordinary repository work remains the smaller
  route there.
- **Smallest useful dose:** One observable cue, one protected contract, one
  owning surface, one primary move, one receipt, and one return condition.
- **Interactions:** Repository re-entry establishes current truth;
  source-authority mapping identifies the owner; bounded support routing can
  execute a finite delegated move. This skill owns the recovery selection and
  verified return.
- **Rest or release when:** The replacement state is verified, an accountable
  receiver holds the remaining move, or a deliberate hold-open state has a
  named return condition.

## Rules

### Rule: Observable state precedes interpretation

Describe what happened before assigning cause. Name the failing command,
status class, exact coordinate, unavailable source, stale handoff record, or
conflicting state and state the consequence for the current decision. Treat people and
collaborators as participants in recovery rather than sources of blame.

### Rule: Whether the gap is useful and its consequence remain separate

An unresolved difference may be generative, neutral, coordination-blocking,
harmful, or still unknown. Preserve a useful gap. Route a blocking gap. Gather
only enough additional context to classify an unknown gap without turning
recovery into an open-ended investigation.

### Rule: Higher-fidelity constraints survive the route

Keep accepted source, sealed bytes, fixed digests, release subjects, privacy,
publication boundaries, permissions, and decision authority intact. When goal
fidelity is uneven, the recovery move serves the highest-consequence invariant
before it improves convenience or structure.

### Rule: One primary move has one owning surface

Select the narrowest surface that can change the affected state. Supporting
checks may inform that move, while one receiver retains responsibility for its
result. A repository failure can route to source, workflow configuration,
credential administration, a release owner, or a human decision without
turning every adjacent surface into an active workstream.

### Rule: Repeated execution requires a changed signal

Declare the stopping event before a retry. Another attempt follows a changed
credential, configuration, coordinate, source revision, environment, or
diagnostic capability that could alter the result. An unchanged failure is a
receipt for the current route, not an invitation to repeat it.

### Rule: Receipts state both reach and boundary

Record what the observation establishes, what it leaves open, and which exact
receiver can make the next decision. Keep raw logs, protected response data,
credentials, private locators, and account details with their existing
authorized owner. A public-safe receipt carries only the decision-changing
summary.

### Rule: Recovery is reviewed by dimensions

Name which dimensions became workable and which remain strained. Authentication
can be restored while repository authorization remains open; source reachability
can return while release acceptance remains pending. A calm explanation and a
green local test are useful evidence for their named dimensions only.

### Rule: History and re-entry remain reachable

Preserve the prior failure, accepted source, superseded route, and current
handoff through the nearest existing carrier. Prefer the pull request, Issue,
workflow result, branch record, or threadkeeping surface that already owns the
state. Another recovery artifact earns persistence only when it changes a
future decision.

## Pattern map

Use ordinary language first. A geometry name is optional shorthand when it
helps select rather than dramatize the move.

| Observable shape | Smallest fitting move | Workable replacement state |
| --- | --- | --- |
| A retry loop repeats one unchanged failure | Break the cycle and retain one decision-bearing signal | One changed prerequisite before another attempt |
| Accumulated notes, branches, or diagnostics block access | Reduce the active set and index the reachable remainder | One navigable current front with archive pointers |
| Two contracts, coordinates, or authority layers have slipped apart | Restate the shared reference and route to the owner of the seam | A verified relation that can carry the next action |
| One explanation has hardened before evidence distinguishes causes | Split it into bounded hypotheses and select the smallest discriminating observation | Several inspectable possibilities with one evidence route |
| Effort grows while decision value stays flat | Narrow to the nearest resumable unit and declare the stopping event | A smaller continuation with explicit loss and return |
| Several readings remain valid | Preserve the sightlines and choose a provisional working position | A revisable position with uncertainty and alternatives visible |

## Operating sequence

1. **Recover the contract:** Resolve the current task, accepted source,
   decision boundary, and exact state from which continuation should resume.
2. **Record the strain:** State the observable cue, consequence, prior attempts,
   and evidence already available.
3. **Assess the gap:** Decide whether it is useful and name its consequence,
   then preserve every active privacy, permission, publication, safety, and
   authority boundary.
4. **Select scope and owner:** Choose the smallest scope and the surface that
   can actually change the affected state.
5. **Choose one move:** Name the primary recovery action, its permitted effects,
   its stopping event, and the receipt it must return.
6. **Activate with authority:** Perform the move only through authority already
   present in the task or route it to the accountable receiver.
7. **Verify the replacement state:** Use the smallest observation that answers
   the recovery question. State restored and remaining dimensions separately.
8. **Return to the work:** Leave the current source, decision-bearing receipt,
   next receiver, and exact event that permits re-entry.

## Representative scenario

### Scenario: Authentication succeeds while one private source remains forbidden

Given a hosted proof authenticates its configured credential<br>
And the first exact private-source request returns a status that cannot establish
repository read access<br>
And an independently authorized observation confirms the repository and pinned
source coordinate remain healthy<br>
When recovery routing selects the next move<br>
Then the accepted release subject and pending observation remain unchanged<br>
And the response body, headers, account identity, and credential remain inside
their protected boundary<br>
And the route returns the permission or repository-selection check to the
accountable owner of the workflow credential's repository grant or repository
selection<br>
And another hosted proof begins only after that configuration changes

## Source and transfer note

This first repository-local version adapts authorized Recovery Routing and
Failure Geometry source material into a self-contained engineering
collaboration contract. The source collection remains with its steward. The
skill carries only the transferable distinctions exercised here: observable
strain, whether a gap is useful, smallest adequate scope, one owning surface,
authorized activation, decision-bearing receipt, dimensional outcome review,
and exact re-entry.

## Completion

Recovery routing completes when the collaboration has either verified a
workable replacement state or handed the remaining move to a receiver that can
change it, and when another collaborator can resume from the named source,
receipt, and re-entry event. A materially different failure shape, a near miss,
or a receiver that cannot act reopens the skill for revision.
