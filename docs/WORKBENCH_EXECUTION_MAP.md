## Apply skills where they change the work

The capability slice exercises schema ownership, bounded projections, and
state-to-view agreement. Its
[draft capability-projection skill](skill-drafts/runtime-capability-projection/SKILL.md)
captures that reusable boundary. Focused fixtures test adapter/lifetime agreement,
strict input admission, detached outputs, route correspondence, and scriptless
runtime wording. A fixture passing establishes that fixture's behavior; configured
database execution remains its own observation.

Use `supportive-change-writing` throughout prose and instructions. State the
action a reader can take, identify the actor responsible for it, and pair a
material boundary with its useful next route. Use `issue-chain-stewardship` to
advance the chain only when the preceding result is available to its receiver.
Use `uv-backed-python-execution` for authorized Python checks, and the existing
focused browser patterns for visible interaction changes.

## Cultivate from observed boundaries

Three candidate skills receive a concrete exercise before activation:

1. **Owned database lifecycle:** disposable, retained, and external database
   profiles whose cleanup and recovery authority remain explicit.
2. **Reviewed classification selection:** prepared catalogs with bounded lookup,
   effective-time selection, overlap decisions, and preserved raw labels.
3. **Finite failure laboratory:** named failure fixtures, interruption, recovery,
   resource ownership, and evidence that distinguishes a demonstrated outcome
   from a merely selected scenario.

Draft or revise each skill when an implementation exposes a repeatable decision
or consequential boundary. `declarative-skill-authoring` supplies its contract,
rules, smallest useful sequence, counterexample, and re-entry conditions.
`collaboration-accounting` routes an exercise into revision, reuse, continued
observation, or retirement. A candidate's existence alone establishes its topic;
its application evidence establishes whether it helps.
