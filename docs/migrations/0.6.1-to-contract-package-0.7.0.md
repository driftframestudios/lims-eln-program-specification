# Receive the installed lifecycle admission API

Package 0.7.0 adds `lims_eln_contracts.database_lifecycle` and the optional
`lifecycle` dependency profile (`jsonschema>=4.23,<5`). Existing model APIs and
the twelve generated schema resources retain their meanings. The root lifecycle
1.0.0 and capability v1 schemas are copied byte for byte into a separate authored
resource inventory. The existing schema generation/check command maintains
that equality; each root schema remains its structural source of truth.

The [package coordinate](../../release/contract-package-coordinate.json) carries
the exact reviewed source commit and scoped package digest. A receiver installs:

```text
lims-eln-program-specification[lifecycle] @ git+https://github.com/driftframestudios/lims-eln-program-specification.git@<reviewed-full-commit>
```

Replace the placeholder with that reviewed coordinate. Use a dedicated proof
environment when the application retains an earlier accepted package. Check
PEP 610 repository/revision/commit, distribution and import versions, the scoped
package digest, and the two exact schema digests from the
[lifecycle guide](../DATABASE_LIFECYCLE.md). Keep the source revision trusted by
the receiver independent of the incoming document's claim.

`LifecycleSource(source_ref, revision, schema_digest)` binds receiver trust.
`admit_lifecycle_profile(payload, expected_source=source, capability_payload=...)`
returns an immutable `AdmittedLifecycleProfile` or a fixed-code
`LifecycleAdmissionError`. Supply capability bytes when the lifecycle record
claims an observed composition. `python -m lims_eln_contracts.database_lifecycle`
and the repository script provide the same local admission entry.

Enterprise and Governance author their own input records and literal expected
results. Include all three dispositions, requested actions beside readiness,
wrong ownership, stale source/schema/version, external cleanup, failed cleanup,
unresolved state, recreation after removal and capability combinations. Keep
failed records intact when appending resolution. A fresh disposable instance
earns cleanup authority through its own successful creation.

We compared schema-only reception, copied semantic engines, dynamic repository
script loading, and an installed Program-owned API. The installed owner lets
receivers exercise one reviewed semantic contract with independently authored
expectations and recoverable package provenance. An optional dependency profile
keeps lifecycle validation explicit for consumers that need it.

Input parsing and canonical output use bounded bytes (128 KiB per input); schema
validation caps events at 64. Semantic traversal is linear in event count with a
bounded identity set. Module initialization loads two immutable schema byte
strings and constructs reusable validators once. Each call owns its decoded
record and result; caller bytes and earlier returns retain their values.

This handoff establishes documentary consistency and installed-source identity.
Configured PostgreSQL/Flyway execution, authenticated grants, recovery effects
and accountable acceptance use their respective receiving owners' evidence.
A receiver can restore its previous pinned proof profile while retaining the
record and fixed-code finding for review. Program #79 closes after both receivers
return independent evidence against the reviewed coordinate; runtime launcher
adoption remains in Enterprise #60/#68.
