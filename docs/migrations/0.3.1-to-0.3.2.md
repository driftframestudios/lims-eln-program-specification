# Migration guide: 0.3.1 to 0.3.2

Release `0.3.2` settles the database target decisions that remained implicit in
`0.3.1`. It adds a digest-bound concordance while preserving the evidence
boundary between specification, simulation, synthetic execution, configured
environment operation, and accountable acceptance.

## Consumer actions

1. Update specification bindings from `spec-v0.3.1` to `spec-v0.3.2` and
   governance bindings from `governance-v2.0.1` to `governance-v2.0.2`.
2. Consume `DATA-CONTRACT-001` version `1.1.0`,
   `DATABASE-MIGRATION-CONTRACT-001` version `1.1.0`, and
   `DATABASE-OPEN-RECEIPTS-001` version `1.1.0`.
3. Project `DATA-CONTRACT-CONCORDANCE-001` into the implementation, simulation,
   and governance representations named by the concordance.
4. Qualify PostgreSQL 17 as the runtime, exercise PostgreSQL 16 as the supported
   predecessor upgrade, and preserve PostgreSQL 18 results as portability
   rehearsal evidence.
5. Represent internal identity with UUID and external identity with constrained
   tenant/source-scoped text. Preserve SHA-256 as one semantic value through an
   exactly 32-byte `bytea` domain or constrained lowercase hexadecimal text with
   algorithm, canonicalization, schema, and scope metadata.
6. Bind every scientific result to an assay, analyte, and method numeric
   profile plus raw and canonical unit, conversion, rounding, qualifier,
   reference-range, detection-limit, time, and source-artifact provenance.
7. Treat conditional approval as pending until its conditions close. Preserve
   decision supersession, revocation, and expiry through append-only history.
8. Publish a current synthetic execution receipt and retain configured vendor,
   representative recovery, production operation, and accountable acceptance
   receipts as future observed evidence.

## Compatibility boundary

Legacy temporal text columns remain supported predecessor inputs. Canonical
relations use finite `timestamptz` instants and `date` calendar values. A
narrower numeric physical type remains compatible when its versioned assay
profile fits exactly and retained round-trip evidence demonstrates value
preservation.

The first executable vendor scope contains the canonical PostgreSQL service and
the concrete LabKey adapter. Sapio and Benchling remain successor conformance
targets until configured-environment receipts bind their runtime evidence.

## Settlement evidence

A protected release requires immutable repository coordinates and exact
simulation and governance representation bytes matching the concordance. That
check proves representation identity and contract alignment. Environment and
domain claims continue through their separately owned observed receipts.
