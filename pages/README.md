# Program Pages source

This directory owns the public orientation content for the program Pages
projection. `program-content.json` supplies the visitor copy; the current
constellation, release-role record, status surface, and exact Git revision
supply the authority coordinates used by the builder.

The standard-library builder creates a local candidate outside the worktree:

```sh
python3 scripts/build_pages.py --output ../program-pages-build
python3 scripts/validate_projection.py ../program-pages-build
```

The aggregate creates two isolated builds, compares their complete byte
inventories, validates each projection, and applies the repository secret-shape
scanner to the generated text:

```sh
python3 scripts/verify_pages.py
```

Each ordinary build requires a clean Git worktree and records the verified
exact `HEAD` revision. Unit tests use the explicit `fixture` standing so
mutation cases can exercise the same contracts while source edits are in
progress.

`--canonical-origin` and `--cname` form one optional publication pair. The
origin uses HTTPS, and its hostname matches the CNAME value. Omitting both
creates portable relative-link pages with no domain claim.

The generated directory contains `.nojekyll`, responsive HTML and CSS, a copy
of the authoritative program content, and a complete manifest whose file scope
covers every projection file except the manifest itself. Generated bytes remain
local candidate evidence. A separately authorized publication action can place
reviewed bytes on a publication branch and attach Pages settings or a custom
domain.

Repository skills enter the projection only when their `SKILL.md` front matter
declares `source_band: public_ready`. A present public-ready set receives a
catalog and one source-faithful page per skill. An empty set produces no skill
catalog, while internal and public-possible sources retain their existing
collaboration boundaries.
